# Essai de niri — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**But :** une session niri + Dux Shell à côté de Plasma sur desktop-gab, retirable d'un coup.

**Architecture :** côté système, un module decman `decman/niri.py` (paquets + deux services PAM). Côté utilisateur, `~/.config/niri/config.kdl` dans dotfiles, limité à Arch. Les réglages de Dux Shell restent locaux et se posent à la main.

**Stack :** decman (Python), chezmoi, niri 26.04, Dux Shell 2.0 (`dux-shell`, binaire `dms`), PAM.

**Spec :** `docs/superpowers/specs/2026-10-30-niri-design.md`

## Contraintes globales

- Paquets uniquement depuis `extra` : `niri`, `dux-shell`, `xwayland-satellite`. Aucun paquet AUR, aucune dépendance optionnelle de Dux Shell.
- Rien ne change sous Plasma : `/etc/pam.d/login`, `kde-fingerprint`, `environment.d` et l'autologin (`Session=plasma`) restent intacts.
- Les variables `QT_QPA_PLATFORMTHEME=kde` et `XDG_MENU_PREFIX=plasma-` ne vivent que dans le bloc `environment {}` de `config.kdl`.
- Dux Shell est lancé par `spawn-at-startup "dms" "run"`, pas par une unité systemd.
- Dans les fichiers, les commentaires sont en français. Les messages de commit sont en anglais, sur une ligne courte, avec la ligne `Co-Authored-By` de session.
- **Pas de commit ni de push sans le feu vert de Gabriel** (CLAUDE.md), qui relit à la fin de chaque tâche. Le travail se fait sur une branche `niri` dans chaque dépôt, avec `git branch --show-current` dans le même appel que `git switch -c`.

## Points de vigilance (à tester, non couverts automatiquement)

1. **Douze doigts refusés (ou absents) d’affilée sur le verrou Dux Shell :** on attend le repli sur le mot de passe, pas un verrou bloqué. On ne sait pas si Dux Shell relance la pile U2F après un échec : à constater (tâche 3, étape 6).
2. **Verrou pris pendant que le KVM est basculé :** `u2f-wait-key` attend la clé, et un doigt la déverrouille au retour (tâche 3, étape 6).
3. **Retour à Plasma après un passage par niri :** même thème, même session, aucun agent polkit ni portail en double (tâche 3, étape 8).
4. **`dms auth sync` (lancé quand on coche « clé de sécurité ») ne doit réécrire aucun fichier PAM.** Les deux fichiers posés par decman n'ont pas de bloc DMS : `pam.go` les laisse alors intacts (tâche 3, étape 5).
5. **Réveil derrière le KVM :** relever si l'écran revient, avec `journalctl -t drm-redetect` (tâche 3, étape 7).

### Tâche 1 : module decman `niri`

**Interfaces :**
- Produit : la classe `Niri(Module)`, nommée `"niri"`, sur le modèle de `Desktop` dans `decman/desktop.py`. `@pacman.packages` renvoie les quatre paquets. `files()` renvoie `/etc/pam.d/dankshell` et `/etc/pam.d/dankshell-u2f`, avec `File(source_file="./files/niri/…")`.
- Consomme : `/usr/local/bin/u2f-wait-key`, `/etc/u2f_mappings` et `pam-u2f`, tous trois posés par `desktop.py`.

- [ ] **Étape 1 : écrire `decman/files/niri/dankshell`**, le mot de passe en secours. ### Tâche 3 : mise en route et vérification sur desktop-gab

Ce sont des commandes que Gabriel lance lui-même, en fish. Le builder les lui donne et note les résultats.

- [ ] **Étape 1 :** `sudo decman --source …/decman/source.py`, puis `chezmoi apply ~/.config/niri`.
- [ ] **Étape 2 :** se déconnecter de Plasma. Sur l'écran de connexion, choisir « niri » et taper le mot de passe. On attend la barre de Dux Shell, et `Mod+Shift+/` qui affiche les raccourcis.
- [ ] **Étape 3 :** `Mod+D` ouvre le lanceur, `Mod+T` ouvre kitty. Lancer `notify-send test`, puis `pkexec true` : le prompt polkit qui s'affiche doit être celui de Dux Shell.
- [ ] **Étape 4 : régler Dux Shell** (Réglages → Verrouillage / Énergie). Ces réglages sont dans `~/.config/dms/settings.json`, non versionné.
  - Cocher `enableU2f`, avec `u2fMode` sur « ou ».
  - Activer le raccourci clé de sécurité (`lockScreenSecurityKeyShortcutEnabled`, Ctrl+Q) : la pile U2F ne démarre qu'avec lui ou le bouton.
  - Cocher `lockBeforeSuspend` et laisser `loginctlLockIntegration` coché.
  - Sur secteur : verrou à 5 min, comme le `Timeout` par défaut de kscreenlocker. Extinction de l'écran à 10 min, veille à 15 min, comme Plasma sur desktop-gab (veille à 15 min confirmée par Gabriel).
- [ ] **Étape 5 :** si Dux Shell demande `sudo` pour `dms auth sync`, vérifier ensuite `git diff --no-index` entre `/etc/pam.d/dankshell*` et `decman/files/niri/` : aucune différence attendue. Puis `sudo decman --dry-run` : aucun fichier à réécrire.
- [ ] **Étape 6 : verrou** (`Super+Alt+L`).
  - Ctrl+Q puis un doigt sur la clé déverrouille (dans les 30 s).
  - Avec un doigt non enrôlé trois fois : noter si le mot de passe marche ensuite.
  - Verrouiller, basculer le KVM sur l'autre machine, revenir : un doigt déverrouille.
  - `loginctl show-session $XDG_SESSION_ID -p LockedHint` vaut `yes` pendant le verrou.
- [ ] **Étape 7 : veille.**
  - `systemctl suspend`, puis réveil : le verrou est déjà là.
  - Laisser 5 min sans toucher : le verrou se met.
  - Noter si l'écran revient derrière le KVM, avec `journalctl -t drm-redetect -b`.
- [ ] **Étape 8 : le reste.**
  - Les écrans sont en extension (`niri msg outputs`).
    - Dolphin, lancé par `Mod+D`, garde le thème KDE et son menu « Ouvrir avec ».
  - `kwallet-query -l kdewallet` répond sans prompt.
  - `gpg-agent-display`, KTailctl, pCloud et Rotatrix sont lancés.
- [ ] **Étape 9 :** se déconnecter, choisir Plasma. Plasma est identique, avec son verrou et sa veille habituels. `xdg-mime query default text/plain` et `text/markdown` répondent toujours `org.kde.kate.desktop` : le bloc-notes de Dux Shell déclare ces types, sans défaut explicite dans `mimeapps.list` (sinon, y fixer Kate dans dotfiles). Reporter les résultats des étapes 2 à 9 dans `CLAUDE.md`, puis un commit après le feu vert de Gabriel.
